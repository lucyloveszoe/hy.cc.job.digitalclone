2024 continuation of the team's recurring "next-gen Clotho" ambition — the same lineage as 2023's "Project Hydra" vision (confirmed, not just likely, as the direct ancestor: a ww02/01/10/2023 report section is literally headed "Project Hydra (NXG Clotho Platform)" — see [[project-2023-annual-review]]) and a likely ancestor of the 2026 NXG platform work in [[project-nxg-pipeline-and-raptor]], though no document explicitly links all three.

**Earlier MQTT-for-test-observability seed, predating this file's "MQTT already used by TDG" line by over a year (Jan 2023)**: during Clotho V4.0 requirements collection, JJ requested an optional MQTT client feature in Clotho to publish system-column values (top reject params, yield-loss numbers, final test time) to a broker, explicitly to support test observability work with Inari — "not urgent but important." Pushed to V4.1 scope. No confirmation found of whether it was ever built by the 2024 DEC2 investigation's time — see [[project-2023-annual-review]] for detail; treat as an early, possibly-unbuilt backlog seed rather than confirming TDG's small-volume MQTT usage actually traces back to this specific request.

**DEC2 naming and the Kafka-Core pivot actually date to Dec 2023, ~1-2 months before the formalized "Jan-Feb 2024" investigation below**: at the 12/07/2023 Kin Lum/Tingyu session of the SW Team Annual Technical Brainstorming (see [[project-2023-annual-review]]), "NXG Clotho"/"Platform W" was renamed **DEC2 (Domain Edge Computation Cluster)** — "renamed due to fundamentally different scope and duties" — with a one-sentence mission statement: "NXG Platform for domain-wise raw data real time streaming with 'plug-in' style processing." The session also spun off 7 other named candidate projects across 4 domains (Kafka Integration: Gen-QS + Service-Monitoring-upgrade-via-AWS-MSK; Snowflake Integration: FeederDB migration [[project-nxg-pipeline-and-raptor]] + NXG WUDAS consolidation; IaC: Data Retention Policy via IaC, assigned to Ken Sun; Compliance: WSD.Data.Version source control) plus a separate credential-handling-mechanism proposal (also assigned to Ken Sun: a long-term central secrets repo with auto-enforced recycling, AWS-Secrets-Manager-style — motivated by the growing pile of shared PPKs/passwords for CM SFTP and BCT streaming access). By year-end all of these had graduated from "candidate" to officially tracked/named 2024 work items. Early technical validation ran in parallel: Tingyu stood up a real 3-broker AWS MSK cluster (`genq-t1`, us-east-1) with a working producer/2-consumer-group test (12/19/2023), and Yu Han personally ran a local Podman + Kafka + Zookeeper dry-run (12/22/2023) confirming topics/producers/consumers work — both preceding and feeding into the formalized DEC2 investigation below.

**DEC2 (Domain/Distributed Edge Computation Cluster) investigation (Jan-Feb 2024)**: explored building a Kafka-based real-time streaming/plug-in processing layer on top of existing pCD+zDB+Handler+TestPlan architecture (backward compatible, no change to existing tester drive sequence). Benchmarked AWS MSK (managed Kafka) extensively — confirmed low/medium-spec brokers handle small (~1KB) message workloads fine, but large (10MB) messages hit throughput bottlenecks requiring multiple producers/partitions. Consolidated the community's 28-item Clotho enhancement wishlist (originally collected 12/08/2023) into 3 groups (02/02/2024, YK/Yu Han/Kin Lum sync): **Group 1** = requires re-architecture → marked "NXG V1.0"; **Group 2** = real-time comm protocol addable to existing Clotho → marked "Clotho V5.x" (MQTT already used by TDG but capped at small-volume RTS, insufficient for mid/long-term goals); **Group 3** = high-ROI items fitting current architecture → "Clotho 4.x" upgrade cycle.

**KP decision (02/07/2024) — custom on-prem CM Kafka deployment put on hold**: KP judged in-CM custom Kafka technically/operationally too heavy given HA/DR requirements and the team's existing workload, and directed the team to pursue MQTT-based CM migration (Clotho v5.x) plus misc Clotho v4.x upgrades instead, while KP separately evaluates industry "buy" vs. "build" options. Hold this DEC2/Kafka-in-CM discussion until a buy option is ruled out. **Gen-QS** (the AWS-MSK-hosted managed-Kafka backbone-simplification project, distinct from in-CM Kafka) was NOT put on hold — it continued as KP-approved (target 04/26/2024) and reached production-usable state through 2024: Public/Private MSK access points plus Kadeck (MSK monitoring UI) set up by 02/27/2024, and a hybrid access-pattern decision made for CM/BRCM-domain clients (API Gateway + Lambda + Private AP, chosen over a REST proxy or ALB for universality) since raw Kafka ports (909x, then attempted custom-port remap to 80/443) aren't reachable from CM/BRCM domains. **Marked Complete 05/24/2024** (Tingyu/Chao/Ken), on its original target date.

**Clotho V5.1 — Urgent CNTRACE Write Optimization, the low-hanging-fruit spinoff (08/13-09/17/2024)**: while the generic "dynamic testers grouping" solution above stalled, JJ (TDG) clarified the real near-term ask for the Nuwa WW38 production deadline was much narrower: **not** cross-Clotho-instance trace sync (judged "near impossible" to ready by Sep'24, and wouldn't even cut the ~0.6s cntrace prep/write time), but simply changing Clotho's cntrace file writing from sequential to parallel/background-thread compression — a pure performance optimization, no new architecture. YK's profiling found ~99% of sequential-write time is file write+compression (~90% of that is compression alone); a background-write POC cut `ClothoQABinTraceFileWriteFile()` time by 90%+ at the cost of higher CPU utilization during concurrent DUT testing. YK's proposal passed internal review (Kin Lum/Choo-Yau/Yu Han) 08/20/2024 and was marked **Clotho V5.1** (target 09/20/2024). Development, simulated-test-plan verification, and on-tester performance testing with Roey (TDG) all completed by 09/10/2024, showing reduced Index Time and Test Time vs. V5.0 in head-to-head testing; passed a further internal review (YK/Kin Lum/Yu Han/Ken) and shipped as a **Trial Release (V5.1D1)** 09/10/2024 (code branch `clotho-v5100-cntrace-write-performance` in `WSD.Framework.Clotho`). TDG separately parallelized trace-string generation in the Nuwa RF2 test code itself (Roey Jiea validating). As of 09/17/2024, pending trial-run feedback and TDG/PE buy-off — not yet fully closed.

**Site-2-Site technical direction: gRPC ruled out, MQTT confirmed viable (04/15/2025)**: as part of the Clotho V5.3/Site-2-Site Communication investigation (sequenced after WAFERSORT.BSIRREGEN and OKTA/Dual-JWT, both now complete — see above), the team found **gRPC does not work well on .NET Framework** (limited HTTP/2 support, no ASP.NET Core hosting for gRPC-Web) and a full .NET-Core/8/10 migration is currently blocked by test-hardware driver compatibility (drivers only support .NET Framework 4 for the foreseeable future).
