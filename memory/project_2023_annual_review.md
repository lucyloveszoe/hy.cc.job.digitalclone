Synthesized from 47 of Yu Han's weekly "WWL" status reports to KP, covering calendar year 2023 (ww01-ww52; a few week numbers are missing/merged in the source set, e.g. ww04+05, ww20+21, ww29+30, ww48+49). Recurring team: Kin Lum, YK, Choo-Yau, Tingyu, Chao, Jiapeng, Da Wang — the same roster later seen in the 2026 reports (see [[user-role-team]]), confirming multi-year team stability.

**Security & infra hardening (Q1 2023)**: team-wide push to replace identity-based AWS access with AssumeRole + fix Cycode-flagged secrets-in-code across ~45 owned repos. Violations dropped from 9,311 (11/2022 baseline) to <500 "Critical" by 03/21/2023. STMicro AVI Map project (released 12/23/2022) served as the pilot vehicle for this pattern before rolling it out broadly. In parallel: PRDA pipeline migrated from a 2017 home-grown EC2-autoscaling framework to ECS+CI/CD (completed 03/07/2023); an urgent, EOL-driven Aurora MySQL 5.7→8.0 upgrade across Oregon+Singapore clusters completed 03/28/2023 with zero downtime/IP-change surprises. This is a distinct, earlier (Cycode/AssumeRole-based) security-hardening wave from the 2026 "Mythos" program (Claude-based scanning) — see [[project-mythos-security-scanning]] for the current one.

**Data pipeline / CM onboarding expansion**: TnR EBR records migrated off SQLite onto the Genealogy DB + Web API (released 01/10/2023). Wafer-level H2 trace query support added (04/10/2023). LGIT Genealogy DRCR report support added (02/14/2023). AWSC (new qualifying foundry) AOI/DC data path enabled (07/25/2023) as part of a broader Cloud SFTP Data Collection Pilot that completed migrating all 17 CM+type zDB categories from 8 CMs, plus 3 gDB data types (FTP/Gmail/Share-Folder categories), by 08/04/2023 (ahead of its 08/15 target). The durable architecture pattern set here — AWS Transfer Family SFTP with one PPK-keyed account per CM, a static EIP so CMs can whitelist a single fixed address, and BRCM-side access routed over the private VPC IP — became the standard onboarding mechanism reused for later CM/vendor data-collection work (see the SFTP requirement in [[project-amkor-vietnam-expansion]]).

**Dev-Proto / NPI test-data infrastructure**: SJ/Seoul Dev-Proto POC closed 03/21/2023, followed by full Development completing 06/30/2023 — officially announced (Clotho V4.0.0 + WUDAS Dev-Proto sites live) on the strength of just 4 total real production files collected across both target regions (1 from Tokyo, 3 from Oregon), a notably thin production-validation bar before declaring a project done. Key decision: picked Aurora (reusing existing MongoDB+S3+Aurora data-lake stack) over DynamoDB or DocumentDB for the Dev-Proto core DB — reuse-over-new-tech, consistent with the recurring "no re-inventing wheels" / "prefers reusing existing infra" principle in [[feedback-engineering-principles]]. Also benchmarked and picked "single large binary + sequential range access" over "many tiny S3 segment files" for data stitching performance.

**Clotho platform evolution**: V3.3.1 production rollout completed 03/28/2023 (chose gRPC over MQTT for the high-throughput real-time streaming case — MQTT was fine for ~50 msg/sec but gRPC was needed for >1K msg/sec, 100KB/msg scenarios; this decision was explicitly framed as feeding "Project Hydra," below, not just V3.3.1 itself). V4.0 (Dev-Proto support) and a V4.1.0 upgrade cycle followed later in the year. **"Project Hydra" is confirmed, not just plausible, as the early next-generation Clotho platform vision** — the ww02 (01/10/2023) report's own section header labels it "Project Hydra (NXG Clotho Platform)" explicitly. Internally shared 01/10/2023 (root trigger: a 11/09/2022 Chung Sik-facilitated cross-function sync on whether to keep investing in Clotho vs. 3rd-party alternatives, concluding "yes"), with SOW definition targeted Q4'FY23. Architecture vision: not a single application but a cluster of functionality nodes (publishing/API node, result-processing node, handler node(s), analysis/mining node(s), execution node(s)) communicating over a gRPC backbone with no fixed master/slave roles; CSV result format replaced by binary + meta-buddy CSV; considered porting Honeybee/FCM into Hydra as a unified IDE. This is the direct ancestor of the team's later NXG platform work (see [[project-nxg-pipeline-and-raptor]] and [[project-clotho-nxg-magnus-roadmap]]) — the "unconfirmed" flag from an earlier read of this material is resolved.

**Earlier MQTT-for-test-observability seed (Jan 2023, predates the 2024 DEC2 investigation's mention of MQTT already being TDG-used)**: during Clotho V4.0 requirements collection, JJ requested an optional MQTT client feature in Clotho to publish system-column values (top reject params, yield-loss numbers, final test time) to a broker "to support test observability... working with Inari to improve their operation efficiency" — explicitly framed as "not urgent but important." **SQL injection vulnerability found and fixed in Genealogy DB API (04/19-04/26/2023)**: an external reporter (Macros Halder) demonstrated a UNION-based SQL injection against the `ebr_records` query endpoint — root cause was the API's original design choice to accept caller-supplied query-argument strings and stitch them directly into SQL for "flexibility," with no sanitization. Fixed by enforcing parametrized (prepared) SQL statements; the team then audited all other gDB/WUDAS query endpoints for the same string-stitching pattern and found no other instances.

**TLS 1.0/1.1 deprecation forced a second AWS security-upgrade wave (May-June 2023, AWS-mandated deadline 06/28/2023)**: distinct from the AssumeRole/Cycode wave above but overlapping in scope — zDB DAL, ATA library, zDB Transfer, Feeder Worker, and presigned-URL generation all upgraded from .NET 4.5.1 to 4.7.2 (TLS 1.2) with assume-role applied where not already done. One permanent exception surfaced: CM ASE-KH (AKH) could not be moved to AssumeRole at all — its firewall requires a fixed IP allowlist, incompatible with AWS STS's dynamic endpoint — so AKH was deliberately left on legacy credentials with only the TLS upgrade applied, a precedent for any future CM with similar fixed-IP-only firewall constraints.

**STMicro S3-lifecycle gotcha (11/21/2023, Chao/Jiapeng)**: a blanket S3 time-based retention rule deleted an "anchor" full-history header file that StWafer detail processing depended on indefinitely, breaking it silently until Suraya reported it. Permanent fix: move such "immortal" anchor files into a dedicated no-lifecycle-rule bucket (the existing Atropos bucket) rather than relying on retention-prefix conventions to make exceptions.
