**What the docs say (verified from source):**
- DocFx site `http://wsdsgsvc03.sgn.broadcom.net:8080/GenealogyDB.DocFx/` (plain HTTP): 2 articles (End Point, Response Codes) + 62 table pages. Flow: ID.Pass JWT (`%USERPROFILE%\idpass.jwt`) -> `GET https://safelock.wsd.sgn.broadcom.net/authendpoint/accesstoken` -> `POST http://10.202.128.107/v2/genealogyapi/ProcessQuery` (Bearer; body `{table, columns, syscol, args}`) -> **synchronous CSV**. Errors: JSON `{code, note}`; mid-stream failure keeps HTTP 200 and appends JSON after the partial CSV. Proxy config file `https://atropos.s3-ap-southeast-1.amazonaws.com/gdbwebservice.html` returns just the endpoint URL.
- The 2023 PDF User Guide is obsolete (owner, 2026-10-13); nothing about its content (v1 body-token flow, 37 tables, copy-paste errors) is a finding or a baseline any more.
- 62 tables: 15 `npip_*` (PPYCC) + 47 others; 31 have the 5 system columns (file-derived), the 15 npip are DB-native; 7 take empty args (unbounded dump). "One year" windows are 365/366/371 (2/19/16 arguments); item caps run 1 to 600,000 (`customer_lot_info`, `machine_id_info` test_id).
- `ebr_records` alone accepts SQL-fragment operators in args (`like '...'`, `in`, `not like`, `AND`/`OR`). Memory records a UNION SQL injection on this endpoint fixed 04/2023 with parametrized SQL ([[project-2023-annual-review]]); the doc example `like KGJI or like BANS or like RALH and not like _HLB_` has an AND/OR precedence trap (exclusion only binds to RALH).
- Response codes misuse HTTP semantics: 204 "Canceled", 405 "Not authorized", 408 "execution timeout", 501 "worker error".

**Top recommendations (ranked):** (1) HTTPS + DNS name for data endpoint and docs; (2) DocFx as the only reference (obsolete PDF removed from Box/Atropos links), generated from a table-descriptor JSON; (3) fix docs (limits table, tz/range rule, "always list columns", mandatory args in words, Access/Freshness pages); (4) move to .NET 10 before .NET 8 EOL **2026-11-10** (gDB WS went to ASP.NET 8 in 2025; team template `WSD.AspNetCoreReact` is .NET 10); (5) structured filters for `ebr_records` (string form kept as alias, negative tests into Mythos delta scan); (6) real HTTP codes + problem+json + truncation signal (Parquet footer or trailer); (7) `/schema`, `/validate`, `modified_since` + soft-delete, per-table-group scopes (PPYCC financial and shipping restricted, mask `Receiver_Email`); (8) later: NPI project-level read by `flash_code`, SDK `gdb` module in existing WUDAS SDK family, `file_id` accepted by File Access API (gDB is the file catalog File Access lacks), agent tool set after the GTO review gate in [[project-wsd-data-access-copilot]]. Renames of typo columns (`PE_Name_Requetor`, `yield_quater_fiscal`, `Die_Class_code` vs `Die_Class_Code`) wait for one batched release with compatibility views per [[feedback-engineering-principles]].

- **Key evidence (`review-evidence/arg_grammar_stats.py`):** 54 of 62 tables have argument sets (93 sets, 282 arguments); every argument is a comma-separated value list (238, 84%) or an inclusive date range (44, 16%); no other kind. `ebr_records` alone adds per-field operators (`=,!=,>,>=,<,<=,in,like,not like`, AND/OR) and the doc restricts conditions to the argument's own field (cross-field OR is the documented invalid example) -> refines D2: surface is a single-field boolean expression, small enough to parse to a tree. 7 tables take empty args; `ebr_records_distinct` note says operators supported but page says empty args [verify].
- **Cross-family insight:** gDB `args`, WUDAS SQL (=,IN,range,IS NULL,LIKE,AND, no OR/JOIN/aggregate in ~201 examples), OEE (required filters, comma lists, date window) and STAVI share one typed `where` model over a small closed operator set (eq,ne,in,gt,gte,lt,lte,between,like,not_like,is_null,is_not_null, and/or within one field). gDB is close on rules 4 and 7, far on 1,3,5,6, N/A on 2,8; WUDAS is the opposite (close on rule 2) -> U3 could read "WUDAS + gDB". Inclusive date ranges (gDB) conflict with rule 4 half-open UTC (decision G4).
- **PPYCC read-model (inferred from columns):** 15 npip tables ~ 5 resources + facets: shipment (`main_display`, key auto_id) -> lots (`split_display`.main_id) and AWB (`awb_display`.auto_id = main.awb_id, inferred); NPI project by `flash_code` (8 tables); wafer yield actual; wafer rate (financial, restricted); facets (`*_distinct`).
