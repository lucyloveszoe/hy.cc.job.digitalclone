**What the doc defines:** base `https://<host>/api/v1/wafer`; 7 ops: `POST /regen` (multipart, 202+Location), `GET /regen/{id}` (universal shape: progress/regen_output_files/errors always present), `DELETE /regen/{id}` (cancel, 409 if not QUEUE/IN_PROGRESS), `GET .../downloads?types=` (safelock URLs), `POST .../zdb-pushes` (201, skips already-pushed files silently), `GET .../zdb-pushes/{push_id}`, `GET .../zdb-push-status` (new 09-09, per-file rollup, COMPLETE>IN_PROGRESS>QUEUE>ERROR, NOT_PUSHED). States QUEUE/IN_PROGRESS/COMPLETE/PARTIAL_SUCCESS/ERROR/CANCELED. Auth line: RSA-signed JWT bearer "alongside the site's existing Okta cookie/OIDC".

**Position:** already follows most unification rules (real HTTP codes, problem+json, 202+Location, GET reads, no GET body); suggested as reference for async-task and mutation patterns in [[project-wsd-api-unification-2026-10]]. Key message: still a proposal, so breaking contract changes cost nothing now.

**Findings (IDs in the doc):** S1-S9 under-specified (`pcd_package` inputs absent; only 2 submit errors, no 401/403/429; id source; limits/retention; downloads zip/lifetime/bucket path; push edge cases; 3 filename forms; no timestamps/submitter). I1-I9 inconsistencies (DELETE doesn't delete; 409 on cancel retry vs "idempotent"; 202 vs 201 for same pattern; `/zdb-push-status` contradicts the doc's own "status is a property" reasoning; `progress` null while running; `workorder_not_ready` overloaded; push errors no detail; skipped==uploaded; enum tenses). C1-C2 no `GET /regen`, no `GET .../zdb-pushes`. X1-X7 (auth not tied to ID.Pass, cookie+POST/DELETE CSRF [verify], no authz model, production ZDB push no scope/audit, upload hardening, API Gateway 10 MB limit [verify], placeholder error URL). M1-M6 (per-file errors free text, no Retry-After/idempotency key, no OpenAPI, RFC 7807/7231 obsolete -> 9457/9110, contract mixed with history, doc site plain HTTP).

**Proposal:** Tier 0 verify; Tier A P-A1..A15 before v1 freezes (pcd_package spec, complete error catalog, split codes + `retryable`, structured progress, cancel semantics, one 202, `skipped_files`, per-file objects with `source_file`, collections, timestamps, downloads doc, push error detail, state vocabulary, auth/scopes/audit, limits/retention); Tier B P-B1..B5 (Retry-After/Idempotency-Key, `push_eligible`, generated OpenAPI 3.0.3 + Spectral + Arazzo, split docs, RFC refs); Tier C align with `GET /v1/tasks/{id}` and use as mutation reference in the shared kit. Decisions R1-R8 and 13 owner questions in the doc; none answered.
