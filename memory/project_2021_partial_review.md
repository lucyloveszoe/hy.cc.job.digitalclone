Synthesized from 11 of Yu Han's weekly "WWL" status reports to KP: ww40, ww41, ww42, ww44, ww45, ww46, ww47, ww48, ww49, ww50, ww51+52 (2021-10-05 through 2021-12-28, the last report of the year; ww43 and all earlier-2021 weeks were not in the inbox batches, so this is a partial-year archive, unlike the full-year [[project-2023-annual-review]]/[[project-2024-annual-review]]). Team roster matches later years: Kin Lum, YK, Chao, Choo-Yau, Da Wang, Jiapeng, Tingyu, Timmy — confirms team stability going back at least to 2021 (see [[user-role-team]]).

**WUDAS performance investigation and fix (completed 10/19/2021) + legacy zDB ODBC retirement (11/18/2021)**: MUC users reported WUDAS (web query service backed by Snowflake) far slower than legacy ODBC. Root-caused to `wudas_sdk_ms` (job-submit-to-completion latency), not download/CSV-load. Fix bundle: integrated Snowflake .NET connector directly into WUDAS API (removed a Lambda hop), deployed WUDAS API regionally (Frankfurt, Oregon) using API-Gateway where no BRCM VPN existed, sped up initialization (pre-warm Snowflake warehouse, pooled/reused Aurora connections), and switched S3 uploads between single- and multi-part APIs after performance data showed multi-part hurt large-query outlier latency (rolled back 10/13/2021). Result: WUDAS reliability and tail latency beat ODBC; ODBC cut-off extended to 11/18/2021 to give MUC migration time, then all ODBC traffic was formally retired/routed into WUDAS on that date. DSM (Data Service Monitor) 2.0 — a parallel monitoring-framework rebuild (Da Wang/YK) covering generic test/measurement checks, CM share-drive/server-resource monitoring, and mobile alerting — completed and deployed 11/22/2021.

**First AWS credential consolidation / security hardening wave (WSD Data Infrastructure Security Enhancement, initiated 07/28/2021, largely complete by 11/16/2021)**: legacy practice of reusing credentials unsecurely across app/services flagged as a cascading-risk. Yu Han (as AWS admin) created ~59 new scoped AWS credentials across CM-relevant (19) and non-CM (62, later found to need a few more) service accounts, covering Aurora/Mongo/S3/Lambda access for dpatdaemon, pcddaemon, zdbtransfer, notification, logfeeder, logaccess, dsm.service, etc. Completed CM-side recycling first (used SNX as pilot), then BRCM/Cloud consolidation. This is an earlier, distinct security-hardening wave from the 2023 Cycode/AssumeRole program (see [[project-2023-annual-review]]) and the 2025 OKTA/dual-JWT rollout (see [[project-okta-sso-jwt-architecture]]) — same recurring theme of periodic credential-sprawl cleanup, roughly every 2 years.

**pCD Phase III (Multi-SKU/Multi-Process workflow simplification) + Clotho V3.2.0 upgrade — both officially released 12/07/2021, ahead of the 12/10/2021 target**: pCD Phase III redesigned the package structure into BASE+CHILD packages to cut file-count/size churn across SKU/process combinations; PE/TDG (via Yee Seng) approved "Proposal #2" UI design 09/29/2021 with no objection from Penang NPI/Process teams; new pCD Client v4.0.0 (WPF/PRISM) and pCD Web API (ASP.NET Core) shipped with an "Upgrade Mode" UI for base/child package diffing, passed external demo 12/06/2021. Clotho V3.2.0 scope was narrowed to a "Limited Scope" SOW (11/09/2021) after Yu Han flagged a requested 3-step→6-step logic change as too much for this cycle; delivered `SetWaferIDBySite()` API (forbids test plans from returning waferID as a test-parameter column, records it as a system column instead, same pattern as OTP_MODULE_ID), invalid-character rejection on UI inputs, and TestPlanDriver/cross-domain simulation support. Both owners entered a 4-week high-priority post-release support window starting 12/07/2021.

**Wafer Probe Post-Processing ownership transfer to SW team (YK leading, target 12/31/2021)**: multi-month effort (kicked off 06/10/2021) to transfer non-testing wafer post-processing modules from TDG/Kuok Liang to SW team so TDG can focus purely on testing. Discovered post-processing spans 3 separate code bases (Production console, Regen UI tool, Online Regen web) with overlapping but inconsistent logic. 8 of 17 modules completed by year-end 2021 (SDI Regen done 10/05/2021); work paused mid-batch in favor of finishing Clotho V3.2.0 first, then resumed. A related but separate long-term initiative, **"Wafer Prober Post-Processing NXG Re-Architecture"** (YK/Kin Lum/Jiapeng, target 04/04/2022), was spun off to define the future architecture via a dedicated task force over 6-12 months — the ownership-transfer effort is the near-term/tactical piece, NXG re-architecture is the follow-on strategic piece.

**Spotfire V11 upgrade / cloud-vs-on-prem topology decision (POC complete 11/29/2021, deployment target 01/31/2022)**: evaluated 3 deployment topologies via POC. Cloud-only dropped (Infolink/CIFS gaps unfixable — cross-region unmanaged-cloud CIFS access was already rejected by BRCM network/security review as a data-leak risk). Settled on "Mixed" topology: SpotFire DB hosted in AWS Singapore as primary, with SJ Data Room and SG DC as additional server nodes syncing from it (custom sync tool built by Chao); target pushed from 11/29/2021 deployment start → 01/31/2022 completion to align with Feb 2022 production/NPI need. ~$21-22K of new Dell hardware (2x PowerEdge R750) purchased for the SJ Data Room (Chao; PR Log #185, HAT #2297, CAR# CNG-17861, PO #82342, ETA 01-Jan-2022).

**INR P13 zDB shared-folder storage crisis (closed 10/26/2021)**: recurring capacity alerts from low-priority fmtrace (~362GB)/cntrace (~61GB) files piling up faster than Inari IT top-ups could handle; cntrace volume was growing ~1.5M files/month. Closed for the time being after October volume dropped, with Yu Han flagging a "separate INR internet connection" request to Inari for ~Mar/Apr 2022 when volume was expected to double (2022) then 4x (2024). KP's related guidance: avoid "always collect 100% data just in case" — favor in-situ preprocessing over blanket collection.

**AI-DPR / AWS blog co-authorship**: Yu Han, Kin Lum, Jiapeng, Da Wang co-authored an AWS AI/ML blog post with AWS's Marc on the AI-DPR project; KP's condition was no product-detail or test-parameter disclosure. Passed Broadcom-side review 09/18/2021; pending AWS internal review through mid-Nov 2021 (no further update in this batch).

**Google Sites migration (Da Wang leading, target before Dec 2021, completed 11/30/2021)**: migrated ~25 separate WSD SW tool/project sites off Google Classic Sites onto a New-Google-Site landing-page structure (WUDAS, WNF, pCD, zDB, CLEADA, DPAT, Clotho, HoneyBee, FCM, PPYCC, etc.), since the new platform doesn't support file upload (docs moved to Box/Drive with links instead). Landing page went live at sites.google.com/broadcom.com/sw-team-projects/home.

**AWS budget/Reserved-Instance cycle (Dec 2021)**: existing AWS BPO (budget/purchase-order) for compute would be exhausted covering December's cost; Yu Han initiated a new PR request (~$295K, "Dec21-20"), approved by KP, with a new BPO (#8821061160) raised by year-end. Ran in parallel with an EC2/Reserved-Instance consolidation cycle (Kin Lum) that cleaned up existing RI allocations and staged a first round of new RI purchases, deferring the SpotFire cluster's RI purchase (Windows r5.2xlarge) to the Jan 2022 bill pending a performance-validation window. This is the earliest-captured instance of the team's recurring AWS budget-renewal/RI-true-up cycle.

**MongoDB "random slow-down" incident on `clothorawdatav2` (reported 12/15/2021, still monitoring as of 12/28/2021, not fully root-caused)**: recurring CPU spikes tied to connection-count surges on the Clotho raw-data Mongo instance, impacting DPAT processing latency. Immediate workaround was manual `mongod` restarts; Kin Lum added a CloudWatch CPU alarm (>10% sustained across 20/30-min datapoints); Yu Han's mitigation was reducing the Auto Scaling EC2 count from 5→3 to cap concurrent connections from 40→24, plus forcing an instance-type change on restart. No alarms fired after the mitigation, but root cause was not confirmed by year-end.

**AWS Lambda "starts but does nothing until timeout" investigation — closed as not-a-limits-issue (12/07/2021)**: Yu Han escalated to AWS support requesting a concurrency-limit increase to 10,000; AWS's response was that WSD's actual peak concurrency (~235, then ~200) was far under the existing 2,500 limit, so the timeouts were not concurrency-related — AWS pointed back to app-side downstream-connection diagnosis (logging/X-Ray). Filed as an internal SW technical-monitoring watch item rather than an AWS-side fix.

**Type 22 (cntrace) data-sync/history-cleanup investigation**: identified that both Oregon and Singapore Aurora instances run MySQL 5.7, which supports native JSON column queries (`col->"$.xxx"`) — recognized (Yu Han/Kin Lum/Jiapeng, 12/01-12/02/2021) as a viable fix path for Type 22's "read from Mongo then insert to Aurora" inefficiency without a schema rework. Da Wang to turn this into a full optimization proposal (not completed within this batch).

**Earliest CI/CD investigation seed (Timmy, assigned 12/14/2021, leveraging his prior PayPal Java/Jenkins experience)**: initial scoping of two directions — making the AWS Feeder/Auto-Scaling deployment CI/CD-compatible, and making CM-site deployment fully automatic (hybrid, config-driven via S3) — with Kin Lum joining due to overlap with the Wafer Post-Processing NXG re-architecture's release approach. This is the earliest captured precursor to the 2025 WSD.CICD automation program (see [[project-cicd-maintenance-automation]]), roughly 4 years earlier.

**"2023 Nathan Quad-Site Test" / Clotho binary-result-format early scoping (Yu Han, Dec 2021, SW-team resourcing deferred to early Feb 2022)**: TDG-led early architecture talk for a 2023 UHB PAD production vehicle ("Nathan") requiring quad-site test capability, weighing "quad-sites-1-controller" vs "dual-sites x 2-controllers." Included TDG's early ask to store DUT result lines in a new binary format (vs. current text) to shrink file size, with Yu Han clarifying that trace-file conversion (cntrace/fmtrace/wafertrace) would cut size far more than raw-result binary conversion alone. No SW-team resourcing committed yet — flagged as the earliest seed of what became Clotho's binary-result-format direction, well ahead of any active project.

**FCMAnalyzer vs. NI "Neon" decision — punted to Feb 2022**: the in-progress internal debate (see original Oct/Nov 2021 entries) over investing 1-2 engineers for 6-12 months to upgrade FCMAnalyzer vs. adopting NI's still-preliminary Neon tool did not resolve in this batch; per KP's sync with Mitch (12/14/2021), the decision was deliberately queued to revisit around Feb 2022 once NI's official Neon release could be evaluated.
