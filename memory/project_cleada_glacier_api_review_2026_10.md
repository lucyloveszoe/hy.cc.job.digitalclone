**Main findings (G1-G12):** outcome and landing location of a restore never described; no tier, wait, expiry or cost note (AWS tier behaviour is general knowledge, [verify]); `rtype: table` undefined (example tab says "restore file then parse"); `Parameter` in the arg table vs `Parameters` in all examples; no limits or partial-failure rule (code 403 hints partial success); no way to check file or restore state; duplicate (201) and cancel semantics unclear for a side-effecting task, and an S3 restore probably cannot be cancelled once requested ([verify]); no per-account quota, audit or cost attribution; `scope` is client-chosen (`g` here, `m` for DPAT) although the server router already decides lanes by account and task (see [[project-cleada-autoscaling-cluster]]); samples are Windows-only, no polling, C# shadows its static HttpClient.
