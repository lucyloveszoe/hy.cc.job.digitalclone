Major multi-month platform-consolidation initiative: migrating legacy VB6 wafer test-plan code into .NET 6+, absorbing wafer-specific test logic into the Clotho execution engine. The team chose the "Fully Integrated" architecture option (pCD-V + U-Portal) over alternatives. Target: trial release 08/14/2026, production Nov 2026.

This initiative is also where Yu Han enforced the Clotho/pCD architecture boundary principle against a competing Wafer-team proposal — see [[feedback-engineering-principles]].

**Origin (01/07/2025)**: the Wafer-vs-Clotho scope question predates this file's 2026 activity by over a year. A draft SW Team 3-Year Roadmap (12/23/2024) set target dates of Clotho 6.0/6.X for 2025.11 and pCD-IV + Clotho 7.0 (NXG) for 2026.11, with a stated need to decide, no later than 2025.04, whether Wafer testing code would be 100% absorbed into Clotho or 0% isolated — still an open management decision as of 01/07/2025 per [[project-clotho-nxg-magnus-roadmap]]. The "Fully Integrated" pCD-V + U-Portal architecture recorded below is presumably how that question was eventually resolved, though no document in memory explicitly links the two decisions.

**Bridge: "pCD-IV/Wafer/Clotho Design" formal kickoff (05/13/2025–08/29/2025)**: this is the missing link between the Jan-2025 open question and the 2026 activity above — the SW team's formal design project for merging wafer testing into Clotho/pCD, targeting completion of full-scope SOW+SRS design by 08/29/2025 (a date multiple later reports note as already slipping). Key early findings: pCD usage is deployed at Chipbond and Sawnics but Inari has NOT adopted pCD (64-bit gap); there's no direct handshake between the testplan domain and handler domain today — all SOT/EOT flows through the Clotho engine exactly as in module testing, meaning wafer-logic absorption does not require changing the tester drive sequence (the technical basis for the "Fully Integrated" decision above). Also scoped here: closing out the separate "WSD Waveform and Vector Files Management" investigation (closed 07/07/2025, merged into this project) — Waveform files have a "single source of truth" (Waveform Manager, waveform-manager.broadcom.net, enforced unique names) but Vector files do not yet have an equivalent central system; vector files are distributed via Box with standardized names since R2023.

**Design work splits into two parallel tracks (08/12/2025 QBR) — clarifies the V6-vs-V7 naming**: the single "pCD-IV/Wafer/Clotho Design" project above split into two named sub-projects, same core team (KinLum/YK/Tingyu/Choo-Yau/Chao): **"pCD-IV + Clotho V6 for Module Testing"** — the primary, actively-progressing track — and **"pCD-V + Clotho V7 for Wafer"** — explicitly listed as the **"Backup"** (secondary-priority) track this quarter. This file's 2026 activity (VB6 wafer-migration, "Fully Integrated" pCD-V+U-Portal architecture) is about the **V7/Wafer** track — so as of mid-2025 wafer was the *secondary* priority behind Module testing; check [[project-clotho-nxg-magnus-roadmap]] or a possible separate file for the V6/Module track's own progress, since it isn't the focus of what's recorded below.

**Non-Continuous Range Test Limit Handling — architecture decision (10/21-10/28/2025)**: per a request from Tzer Ming, Yu Han/KinLum/YK designed a fix for a gap where a PE's TSF (Pass/Fail Criteria) edit creating a "Non-Continuous range" causes Clotho's raw result files to have "NO HL/LL Limit," which zDB then silently refuses to process — even though non-continuous ranges are a legitimate, intentional non-production use case and per prior PE/TDG agreement must NOT block Clotho from executing the test plan. **Decision**: enforce a "Non-Continuous range" check in both Clotho and pCD Client — Clotho alerts but still executes in SUser (non-production) mode, while both Clotho (in Production/PPUser/VUser mode) and pCD Client reject the test-plan load outright, since pCD-driven results are assumed to always flow through zDB. Originally preferred as a shared library so Clotho and pCD Client consume the same check — **superseded 11/11/2025**: YK investigated modularizing this into Clotho, but the team decided to implement it AS-IS in each codebase instead and closed the modularization investigation. This check now ships as part of Clotho V6's "SLOW" workstream (binary-backward-compatible with Clotho V5.2/pCD-III/pCD-IV, adds support for pCD-IV's `.jsonx` file format alongside the legacy pCD-III `.json`).

**V6/Module track: pCD-IV client development essentially complete (12/02/2025)**: all pCD Client pages (init, file-view, test-process, submit) reached Complete, along with the pCD Web API, TPA CLI (Windows/Linux), full TPA U-Portal (upload/download/history/vector-role management), and legacy pCD-III test-limit/package-restriction changes. **New architecture decision**: TPA's Waveform-file SSOT is split into two zip files — a non-changeable "content" zip and a changeable "extras" zip (with its own `extra.manifest.hash`, distinct from the content zip's `manifest.hash`) — to allow customizable download paths and versioned extras without duplicating content files. Remaining open pieces: Clotho V6 STP (draft in progress) and final pCD Daemon/library testing.

**SW team narrows pCD-V scope, pushing back on wafer team's proposal (12/30/2025)**: the original plan had U-Portal fully covering the Wafer Portal migration (WST2 + Spec conversion), with pCD Client responsible only for packaging/distribution. The wafer team's counter-proposal dropped the U-Portal migration piece but still expected pCD Client to absorb the pCD-irrelevant Spec-conversion workload that had been part of that U-Portal scope. **SW team's new counter-proposal**: exclude Wafer Portal, WST2, and Spec Release from pCD-V coverage entirely — the wafer team keeps ownership of that scope — so SW can focus its limited resources on the higher-value, critical-path item: investigating and optimizing the wafer codebase itself, including resolving behavior like "1st/2nd probe cannot refer to a different recipe." Treat this as a scope-narrowing decision pending wafer team's response, not yet final agreement.

**V6/Module track: CAT-team onboarding issues resolved, remaining infra issues found and fixed (12/16/2025)**: Clotho V6 STP draft and pCD-IV DLL integration into Clotho V6.0 both reached Complete (STP testing on Clotho V6.0D1 now in progress). Kushan's (CAT) large-failure-count issue is fully resolved. Three infra items surfaced while wrapping up: (1) **TPA CLI parallelization** — workaround is running TPA CLI sequentially; root-cause fix (a lock mechanism) in progress; (2) **TPA CLI SSL issue** — root-caused to TLS version negotiation (client fails when offering TLS1.3+TLS1.2 together, but passes with TLS1.2-only) — code updated to probe which SslProtocol works and fall back to None if undetermined, testing in progress; (3) **Dev/Prod isolation for TPA U-Portal** (requested by Kushan) — solved via a dual ID.Pass scheme (separate dev/prod UPortal API endpoints, `:9000` for dev), now Complete. **Git 100MB single-object limit**: confirmed fix is Git LFS on S3 with a GitHub pointer file — the pCD library update for LFS is Complete, pCD Client update still in progress.

**TPA CLI issues both closed; new Git CRLF bug found (12/23/2025)**: TPA CLI **parallelization** closed (root-cause lock mechanism applied) and TPA CLI **SSL/TLS issue** closed (SslProtocol-probing fix confirmed working by both Jay and Kushan) — both formerly-open wrap-up items from 12/16 are done. **New issue**: GitHub's CRLF line-ending conversion causes a file-size mismatch between the Git copy and the local copy of LFS-tracked files — fix options are a global Git setting to disable CRLF conversion entirely, or generating the manifest only *after* git checkout (not before). pCD Daemon's LFS update: daemon update + testing Complete, large-file-caching improvement still in progress. **TPA waveform/vector migration to the new SSOT**: Kushan finished migrating existing waveform files (Complete); Jay's vector-file migration still in progress.

**V6/Module track: Git LFS/CRLF issue fully resolved, TPA SSOT migration fully complete — dev phase wrapping up (12/30/2025)**: pCD Daemon's LFS update+testing and its large-file-cache improvement are both now Complete. **Git CRLF bug root-caused and fixed**: Git only auto-converts LF→CRLF when a file mixes CR+LF and LF; fix applied via a `.gitattributes` entry (`* -text`) that treats every file as binary and disables line-ending conversion entirely on checkout/commit, plus a version-tagged `.gitattributes` that pCD Client auto-downloads from the template repo when a newer version exists. Also fixed: a package-version-list retrieval bug (root cause — `manifest.hash` lived only inside the zip, not on the shared folder; fix — pCD Daemon now also writes a protected `.jsonx` copy of the manifest to the shared folder, with a defined lookup order: `manifest.hash` → `.sjnx` → package zip → not-found exception) and pCD Client now embeds TP/TCF/TL version info into `manifest.hash`. Only remaining piece: bundling a Git-installation prerequisite into the pCD Client installer (in progress). **TPA waveform/vector migration to SSOT is now fully Complete** (both Kushan's waveform migration and Jay's vector migration done) — closing that migration workstream entirely. Next: full integration testing after New Year, sharing with TDG/PE around mid-January 2026.
